# Market analyst: source-pinned native protocol

Original at `393a4539cecc5b19c20f5f80829612cd8abef28a`: `tradingagents/agents/analysts/market_analyst.py` calls `get_stock_data` first, chooses up to eight complementary indicators using exact names, then calls `get_verified_market_snapshot` before any exact OHLCV, level, or indicator assertion. The original deterministic snapshot is in `tradingagents/dataflows/vendors/yahoo/snapshot.py`; it excludes rows after the analysis date, does not forward-fill missing OHLCV, shows latest row and up to 30 recent closes, and computes a fixed indicator set with stockstats. Native calculation from the connected feed is an analogous verification path, not byte-identical stockstats execution.

## Data and capability
1. Fix ticker and analysis date in America/New_York; never request bars later than that date or infer intraday bars from daily bars. Retrieve Schwab current quote separately; distinguish regular-session quote, extended quote, timestamps and flags.
2. Check the *actual exposed tool inventory* for Schwab equity historical bars. If a suitable endpoint exists, request needed daily and (when relevant) intraday history and validate symbol, interval, dates and session. At v0.1.5 the connected Schwab Cloudflare Web inventory exposes quote, option-chain and futures history, but **no equity-history tool**. Futures history cannot substitute for equity bars. Record `SCHWAB_EQUITY_HISTORY=NOT_EXPOSED`; do not imply a failed call or claim Schwab bars were tested.
3. When Schwab equity bars are not exposed or fail validation, request Alpaca `get_stock_bars` with `feed="iex"`, `timeframe="1Day"`, explicit historical start/end or sufficient lookback, `sort="asc"`, and a limit sufficient to cover at least 200 complete trading rows when available. Label `HISTORY_SOURCE=ALPACA_IEX_FALLBACK` and the reason. Use a separate explicit `15Min` request for intraday analysis when needed. Do not blend sources in an indicator series. IEX volume is a venue sample, not consolidated volume.
4. Normalize timestamps to exchange dates; reject out-of-window, duplicate-date, out-of-order, nonnumeric, missing or impossible OHLCV rows (high < max(open,close), low > min(open,close), negative volume). Record raw count, accepted count, first/last date, gaps and adjustment basis if known. A returned row timestamp at 00:00/04:00/05:00 UTC for a daily bar is its trading-date label, not an intraday quote time. If adjustment or corporate-action treatment is not verified, do not assert adjusted history or splice pre/post split data without qualification.
5. Compare the latest historical bar against Schwab's **same-session regular** fields where dates/semantics match. Do not compare extended-session last with daily close as if identical. Report genuine discrepancies with both named feeds, session and timestamps; do not overwrite the historical series with a quote value.

## Indicator selection and verification
Select no more than eight complementary names from `close_50_sma`, `close_200_sma`, `close_10_ema`, `macd`, `macds`, `macdh`, `rsi`, `boll`, `boll_ub`, `boll_lb`, `atr`, `vwma`. State why each selected family suits the observed regime. MACD components and Bollinger components are one family each, even if several exact names are selected. The original prompt did not offer a stand-alone 20 SMA except `boll`; do not silently replace its 50/200 SMA trend check with 20 SMA.

Perform deterministic arithmetic from validated bars before writing exact values. Define conventions alongside outputs: SMA is the mean of the last N closes (at least N complete bars); EMA uses a stated seed and alpha 2/(N+1), with warm-up (e.g., 200+ prior rows); MACD is EMA12−EMA26 with EMA9 signal and histogram difference; Bollinger uses 20 closes and stated 2× standard-deviation convention; ATR uses true ranges with previous close and stated Wilder or simple smoothing; RSI uses a stated 14-period Wilder smoothing and sufficient warm-up; VWMA is sum(close×volume)/sum(volume) over a stated window. If the convention or samples are inadequate, label that numeric indicator unavailable. Do not call a simple 14-bar gain/loss ratio equivalent to stockstats RSI. Never mix IEX volume with Schwab consolidated-volume assertions.

Build a **verified market snapshot** after calculations: requested date, latest accepted trading date and OHLCV, source/feed and accepted-row count, indicator names/value/convention, and up to 30 dated closes. Every exact level or percentage in the analyst report must trace to this snapshot or to an explicitly dated raw bar. Show arithmetic for claimed returns. Support/resistance is a hypothesis from cited swing dates/prices unless repeated tests have been verified; do not describe bounces or backtests without actual observations. End with the original analyst's compact key-point Markdown table.

## Gate and example
`VERIFIED` for the Market role requires a valid dated bar set, an independently checked latest row, enough history for the *claimed* indicators, and a source/timestamp-labeled quote or a clear quote-unavailable state. Missing long lookback means omit that indicator; a usable shorter trend assessment may be `PARTIAL`. Bad or missing bars means `UNAVAILABLE` for technical claims. No role status can be earned from a tool returning HTTP success alone.

Connected-source smoke check on GOOGL for 2026-11-16 (research-only, after close): Alpaca IEX returned 276 daily rows from 2025-10-13 through 2026-11-16. Last row O/H/L/C 293.935/294.12/282.975/283.795 and IEX volume 1,525,687. Deterministic closing-price SMA50 = 327.0966 and SMA200 = 338.2020 from those rows. Schwab's separate regular-market last was 283.72 with a later extended print; venue/session distinctions apply. This smoke check validates fallback retrieval and these two calculations, not all original indicators, corporate-action adjustment, full-market volume, or a complete seven-role run.

## Cloudflare Worker implementation finding and acceptance

Read-only inspection of the deployed `schwab-mcp-staging` Worker on 2026-11-16 found an internal `ScannerMarketDataReadOnly.readMarketData({kind:"equity_history", ...})` implementation. Its validation permits only a fixed ticker allowlist, frequencyMinutes 5 or 30, and at most 7 or 21 calendar days respectively. It is a service-binding entrypoint, absent from the Worker's published MCP `tools` list and `handleMcp` dispatch. The published `schwab_futures_history` is unrelated. Therefore ChatGPT cannot currently call equity bars from this connection, and the internal method cannot supply 200 complete daily trading bars.

Recommended focused change in the existing Worker source, preserving OAuth and bindings: add a read-only `schwab_equity_history` MCP tool for daily and 15-minute equity candles. Validate symbol, frequency, bounded start/end, payload shape, OHLCV sanity, ascending timestamps, max rows, as-of cutoff and provider metadata; call Schwab Market Data API `/pricehistory` with appropriate daily or minute frequency. Preserve `isDelayed`, retrieval time, coverage and errors; do not expose access tokens. Publish it in both the MCP `tools` array and `handleMcp` dispatch, retaining the existing internal RPC contract. Deploy from version-controlled Worker source with the existing bindings and a reversible version. Do not replace a 975 KB generated bundle through ad hoc string substitution.

Acceptance: (1) MCP tools/list advertises `schwab_equity_history`; (2) GOOGL daily request returns at least 200 valid distinct trading rows or a specific source failure; (3) GOOGL 15-minute request returns bounded regular-session rows; (4) no future/duplicate/bad OHLCV rows; (5) compare same-date Schwab/Alpaca closes with venue/adjustment disclosure; (6) Market snapshot computes 50/200 SMA from Schwab daily rows when valid; (7) induced Schwab failure triggers explicitly labeled Alpaca IEX fallback; (8) quote, chain, OAuth and futures tools still work. Only then change `HISTORY_SOURCE` to Schwab primary. This is an implementation requirement, not a completed integration test.
